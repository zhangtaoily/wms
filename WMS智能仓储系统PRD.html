1 背景与目标

现状问题：纱线纺织产品以"批号 + 缸号 + 箱码"为最小追溯单元，传统 ERP 仓储模块只能管理到单据与数量，无法覆盖以下场景：

  • 纱线入库前需先收录箱码（码单）、再组托（托盘）上架，人工纸单易错漏；
  • 立体仓库（ASRS）设备作业与业务单据脱节，下架/回库依赖人工指挥；
  • 批号、缸号、标重、纱支、原料成分等行业属性的库存台账与追溯难以支撑；
  • 仓内作业（移库、盘存、调拨）缺少移动端（PDA）支持。

产品响应：建设独立 WMS，承接 ERP 下游仓储执行：以条码为纽带把单据、箱码、托盘、仓位、设备任务串联起来，并将执行结果回写 ERP。

可观察的目标结果：

  • 任一箱码可追溯到批号、缸号、托盘、仓位、经手人与时间；
  • 出入库单据从 ERP 引入后，无需重复录单即可完成作业并回写；
  • 普通仓（人工 + PDA）与立库（扫码终端 + 输送线）在同一单据体系下闭环；
  • 库存以"库存批次 × 仓位 × 托盘 × 箱码"多粒度实时可见。

系统的核心价值链是一条"ERP 引入 → 仓储执行 → 台账更新 → 回写 ERP → 同步对账"的闭环：

闭环成立的判定条件：任一 ERP 引入单据，最终呈现"出/入库单 生效 + 同步成功"两个终态；若同步未成功，停留在 未同步 并可再次触发同步（见 7.4）。

5 功能需求

5.1 入库链路（收货清单 → 码单收录 → 组托 → 入库单）

目的：把 ERP 采购/生产/调拨的到货，转化为按"箱码-托盘-仓位"管理的在库批次，并回写 ERP。

FR-01 收货清单

  • 触发：采购/调拨在途到货前，系统接收 ERP 收料数据，仓管员查看收货清单。
  • 处理规则：记录供应商、供应商编码、发货单号、出库日期；在途状态为 在途 → 已到货 → 已收货。
  • 结果：确认收货后进入码单收录环节；清单作为到货计划的依据（不直接生成库存）。

FR-02 码单收录

  • 触发：仓管员在 PC 或 PDA 上对到货纱箱逐一扫描箱码。
  • 处理规则：按业务类型（采购入库/产件入库/调拨入库/销售入库等）建单；每箱记录批号、缸号、标重；单据明细支持"扫描引入"。
  • 结果：生成箱码台账（箱码信息），累计件量；为组托提供箱码池。

FR-03 组托单

  • 触发：码单收录完成后，仓管员选择组托方式：件入条码组托 / 传入条码组托 / 手动组托。
  • 处理规则：同托箱码归属同一托盘号；记录托盘号、箱码、批号、缸号；PDA 端可扫码组托。
  • 结果：生成托盘台账（托盘信息），托盘成为立库入库与仓内移动的基本单元。

FR-04 入库单

  • 触发：组托完成并上架（普通仓人工/PDA 确认，立库由入库任务驱动）后生成入库单。
  • 处理规则：字段含入库类型（采购/产件/调拨/样品/退料等）、作业方式（条码作业/批次作业）、仓库、批号、缸号、标重、箱数；支持"提交"后生效。
  • 结果：生效后增加库存批次台账；执行"同步 ERP"生成 ERP 入库单号，同步状态置为成功。
  • 状态与例外：制作中可编辑删除；生效后不可编辑；同步失败停留在未同步，可重新同步。

5.2 出库链路（出库通知 → 出库单 → 立库下架/拣货 → 同步 ERP）

FR-05 出库通知

  • 触发：仓管员依次执行"导入发货通知 / 导入领料申请 / 导入采购退料"，或手工新建。
  • 处理规则：明细含发货类型、批号、缸号、物料、色号（条染/统染/公司/客户）、标重、仓库、仓位；物料批发明细支持"引入通知单 / 扫描引入"。
  • 结果：生效后作为出库作业的需求来源；状态 制单中 → 生效。

FR-06 出库单

  • 触发：依据出库通知生成；或手工新增。
  • 处理规则：出库类型（销售/调拨/领料/直接拣货/复磅检/采购退料/样品）；作业方式（条码/批次）；记录 ERP 订单单号、ERP 出库单号。
  • 结果：提交生效后扣减库存批次台账；"同步 ERP"成功后回写 ERP 出库单号。

FR-07 立库扫码终端（条码出库作业）

  • 触发：立库操作员在终端选择"条码出库 / 空托出库 / 条码出库测试"。
  • 处理规则：扫描/输入批次任务号检索；选择月台回路（月台1~8号回路、出口自动、5#自动线、自动组托组箱共 11 个）；从"业务批次任务 / 托盘批次任务"双面板中选定任务。
  • 结果：点击"开始作业"下发任务，输送线启动选托下架；未选任务时阻断并提示"请选择有效的批次任务，再进行选托下架作业！"。
  • 留痕：执行过程写入仓储任务、作业任务与作业日志。

5.3 库内管理（移库 / 盘存）

FR-08 移库单

  • 触发：仓管员新建移库单（PC/PDA 均可发起）。
  • 处理规则：四种类型（托盘挪库/编码移库/批次移库/空托移库）；记录源仓位与目标仓位；明细按托盘/箱/批次层级。
  • 结果：生效后更新托盘与箱码的仓位归属，库存批次总量不变；不回写 ERP（内部调整）。

FR-09 盘存单

  • 触发：仓库主管按周期或事件发起盘存。
  • 处理规则：按仓库/仓位生成盘点范围，逐箱核对批号、缸号、标重；盘盈盘亏记录在盘存明细。
  • 结果：生效后按盘点结果调整库存批次台账。

5.4 立库作业（仓储任务 / 作业任务 / 作业日志）

FR-10 仓储任务

  • 目的：对立库设备任务（入库上架、下架、回库、移库）进行业务级监控。
  • 字段：任务号、任务类型、目标仓位/月台、执行状态、创建/完成时间。

FR-11 作业任务与作业日志

  • 作业任务：设备动作粒度的任务明细（含操作员、设备）。
  • 作业日志：按单据日期检索的设备动作流水，用于追溯与对账。

7 业务闭环规则

7.1 环节①：单据引入（ERP → WMS）

  • 出库通知仅接受三类 ERP 源单：发货通知单、领料申请单、采购退料单；导入时按 ERP 单号去重，重复导入阻断并提示。
  • 收货清单接收在途数据，到货前仅作计划参考，不生成库存。

7.2 环节②③：仓储执行与台账更新

  • 入库以"箱码 → 托盘 → 仓位"三步落账；出库反向消耗，先按批次任务锁库存，下架/拣货确认后扣账。
  • 移库/盘存仅调整台账内部结构（仓位归属/数量校平），不产生 ERP 往来。
  • 每一步作业记录经手人 + 时间戳，作业日志不可修改。

7.3 环节④：单据生效与回写

  • 单据"提交/生效"后才允许同步 ERP；同步内容 = 单据头 + 批次明细 + 回写 ERP 单号。
  • 同步成功的判定：ERP 单号回填且同步状态 = 成功；此时闭环对该单据关闭。

7.4 环节⑤：对账与异常恢复

  • 同步状态为"未同步"的单据可重复触发同步（幂等，以 ERP 单号判重）。
  • 对账不平（WMS 台账 vs ERP 库存）时，以作业日志 + 单据流水定位差异单据，人工核查后重同步或调整。
  • 自动重试策略与告警渠道 [TBD]。
