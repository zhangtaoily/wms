# BUG-10 根因与修复记录（2026-10-24 15:00）

## 现象
列表勾选生效单据 → 删除 → 确认 → HTTP 405 `Request method 'DELETE' not supported`（后端直连同端点正常返回业务拦截）。

## 排查链（5 层深入）
1. 对照实验：后端直连 DELETE 带 id → 业务拦截 200；**无 id 段**（`/WMS_INBOUND` 尾斜杠）→ 405。→ 前端发了空 id。
2. 前端：勾选后 `multiDataList.length`=1 但 `this.ids` 空 → `getSelectedList` 的 `dataList` 行里根本没有 `id` 键。
3. API 验证：动态列表返回行**无 id 键**（SELECT 列完全由 sys_field_config 驱动，主键未配置）→ 引擎级缺陷。
4. 引擎修复①：DynamicsQueryService 两版查询拼列兜底附加 `id` 列（DataViewMetaData 补 fetchColumns 访问器）。
5. 修复后 id 仍异常（boolean/dict 顶替）→ 诊断日志锁定 processRow 入口 id=BigInteger 正常、出口被顶 → **FieldSortPlugin 比较器把所有未配置列（id/_docStatus/_syncRetryable）排同秩（Integer.MAX_VALUE），TreeMap 同秩视为同键互相覆盖** → 行内 id 被插件标记键的值顶掉。

## 修复（3 处）
| 层 | 文件 | 内容 |
|---|---|---|
| 引擎 | FieldSortPlugin | 比较器同秩按字段名打破平局（未配置列不再互相覆盖；此缺陷同样影响 CRM 基线） |
| 引擎 | DynamicsQueryService ×2 + DataViewMetaData | SELECT 列兜底附加主键 id（字段配置未含主键时）；DataViewMetaData 补 fetchColumns() |
| 前端 | DynamicList/index.vue | getSelectedList id 类型归一比较；handleDelete 空选择守卫（另发现删除按钮无选择时本就禁用，守卫兜底） |

## 回归证据
- API：WMS_INBOUND 行 id=雪花号（字符串防精度）；_syncRetryable 布尔正确归位（修复前被顶掉）
- UI：勾选生效行→删除→确认 → toast「状态为制单中、审核驳回的数据才允许删除！」（业务拦截，bug10_fixed_delete_block.png）
- 附带收益：列表行现在携带主键，行级操作（编辑/删除/复制/联查）在所有未配置 id 列的模块上恢复可用

# BUG-11 追加记录（2026-10-24 15:30）：出库通知列表“系统未知错误”

## 现象
用户报：出库通知列表报「系统未知错误，请反馈给管理员」。

## 根因（BUG-10 修复的连带暴露，两层）
1. **BUG-11a（我的 BUG-10 兜底引入）**：兜底判断正则写成 `matches(".*id.*")`——Java 源码里 `` 被 Python 写入时变成**字面退格符**而非正则词边界，判断永远不命中 → 兜底必然追加裸 `id`；且未限定表名。
2. **触发面**：过滤方案弹窗查询（sys_filter_scheme LEFT JOIN sys_user）中 `id` 歧义 → `Column 'id' in field list is ambiguous` → 出库通知列表 500。
3. **连带暴露 BUG-11b（M6 初始化脚本自身缺陷）**：WMS_CODE_COLLECT 的 boxBarcode 列配置 `sql_column='b.box_barcode'` 引用单表查询不存在的别名 `b`（脚本误写）→ 码单收录列表 500。

## 修复
| 项 | 内容 |
|---|---|
| 兜底判断 | 改为**别名精确匹配** hasIdAlias()（取列表达式末段 alias 比对 "id"），不再用正则 |
| 兜底列限定表名 | cla 版 `tableName + ".id"`；dataView 版经 DataViewMetaData.fetchMainTableName() 限定，JOIN 查询不再歧义 |
| DataViewMetaData | 补 fetchMainTableName() 访问器 |
| M6 脚本/活库 | boxBarcode 列 sql_column 改为标量子查询（取首箱码），保留条码号列与 PDA scan_input 标记 |

## 回归（API 全模块）
WMS_OUT_NOTICE（报障模块，2 行正常）/WMS_INBOUND/WAREHOUSE/SYNC_RECORD/WMS_STOCK_MOVE/WMS_STOCK_COUNT/WMS_OUTBOUND（含 id 行主键）/SYS_FILTER_SCHEME（JOIN，id=1）/dialog 过滤方案查询 ×2 —— 全部 200。
WMS_CODE_COLLECT 恢复（total=10，首箱码 BOX-E2E-001 正确显示）。
UI：出库通知列表 DOM 验证 2 行渲染、无错误 toast（截图 surface 偶发超时，以 DOM 断言为证）。

# 功能增强：字段配置 SQL 表达式「逻辑列自动解析」（2026-10-24 15:40）

## 背景与目标
原配置方式要求实施人员知道后端表名/别名/JOIN 关系才能写 sql_column（此前 b.box_barcode、JOIN 歧义两个事故均源于此）。
本次将简单场景降为零 SQL 知识，高级场景原样保留。

## 三层语义（引擎 DynamicsQueryService 统一解析，两条查询路径生效）
| 配置写法 | 引擎行为 |
|---|---|
| **sql_column 留空** | 按列名驼峰转下划线在主表实体解析；命中 → 主表限定输出；未命中 → NULL 列（配置缺失不中断列表） |
| **简单列名**（驼峰/下划线均可，如 warehouseName、inbound_no） | 同上解析；主表未命中保持原样（兼容 DataView 自带 join 别名列） |
| **高级写法**（表名.列 / CASE WHEN / 子查询等含 . 空格 括号） | 原样兼容，行为不变 |

主键 id 兜底保留（字段配置未含主键时自动附加主表.id）。

## 管理页
字段配置编辑弹窗 SQL表达式 项新增填写指引（截图 fieldconfig_logical_column_tip.png）。

## 验证
| 用例 | 结果 |
|---|---|
| 留空 + 列名 auditor（驼峰）→ 主表解析 | ✅ 返回生效人 id |
| 简单列名 inboundDate（驼峰写法）→ 主表解析 | ✅ 返回 2026-10-24 |
| 全模块回归（仓库/入库/出库/通知/移库/盘存/码单/同步监控） | ✅ 行主键与原列不受影响 |
| JOIN 型 dialog 查询（过滤方案）| ✅ 不再歧义 |
| 码单收录子查询列 | ✅ 正常 |
